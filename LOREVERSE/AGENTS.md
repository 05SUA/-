# LOREVERSE 개발 지침

- 모든 작업 전에 이 폴더의 [prd.md](prd.md)를 읽고 기존 구현과 변경사항을 확인한다. 프로젝트 요구사항의 기준은 PRD다. 확정된 서비스 콘셉트·디자인·정보 구조·기술 스택은 사용자 확인 없이 바꾸지 않는다.
- PRD §12 순서대로 한 단계씩 구현·검증·보고한다. 처음에는 01단계만 진행한다. 현재 단계에 없는 서비스 페이지, UI, 인증 및 창작 기능을 미리 구현하지 않는다. P0를 검증한 후 P1을 확장한다.
- LOREVERSE는 세계관·인물·관계·대화·이야기를 만드는 창작 도구다. AI는 초안을 제안하며 사용자가 공식 설정을 결정한다. A. DIMENSION / 01. PORTAL, 확정 카피·색상·서체·레이아웃과 14개 페이지 유형은 PRD §2–3을 따른다. 한국어 UI와 영문 브랜드 제목, 반응형과 키보드 접근성을 유지한다.
- HTML5, CSS3, Vanilla JavaScript(Fetch), PHP 8.x(PDO MySQL/cURL/세션), InnoDB·utf8mb4 MySQL 호환 DB, Gemini Developer API를 사용한다. 브라우저는 동일 호스트 PHP API를 호출한다. PHP에서 HTTPS로 Gemini를 호출한다. 운영에 Node.js, URL rewrite, SSH, cron 및 상시 프로세스를 요구하지 않는다. 로컬 XAMPP·phpMyAdmin과 InfinityFree 우선 배포를 유지한다.
- 실제 MySQL 영속 저장과 실제 Gemini 호출로 기능을 검증한다. 가짜 저장, 하드코딩된 AI 응답, 가짜 통계·배포 URL, 작동하지 않는 기능을 완료 상태로 표시하지 않는다. 생성과 저장을 분리하고 사용자 고정값과 공식 반영 승인 규칙을 준수한다.
- API 키·비밀번호는 비공개 서버 설정에만 둔다. 채팅·Git·브라우저·오류·로그로 내보내지 않는다. 공개 웹 루트에는 공개 파일만 둔다. 운영 HTTPS, 직접 접근 차단, 세션·CSRF·소유권 검증, PDO 준비 구문, 서버 입력 및 Gemini 응답 검증을 PRD §6–10에 맞춰 적용한다.
- 운영 비밀·계정·URL이나 실제 모델이 필요하면 필요한 입력과 설정 위치를 설명하고 해당 검증을 미완료로 기록한다. 사용자 승인 없이 외부 배포나 비용 발생 작업을 수행하지 않는다. 운영 진단 후 임시 진단 파일을 제거한다.
- 기존 구현을 수정할 때 목적과 범위를 먼저 설명하고 필요한 부분만 바꾼다. 스키마 변경 시 문서를 함께 갱신한다. 단계별 결과에 변경 파일, 실행 방법, 실행한 테스트와 결과, 미검증 항목과 필요한 정보를 기록한다.
